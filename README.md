# Empório da Música — Customer Service Agent

Text-message customer service agent for **Empório da Música**, a fictional musical instrument
store in Campo Grande/MS, Brazil. Built as the technical case for the AI Engineer position at
Artefact.

The assistant, **Lia**, answers questions about the catalog, prices, promotions, payment,
shipping, orders, returns, warranty and opening hours. She looks up the store data and the policy
manual through tools, checks her own replies before sending them, and hands over to the human
team whatever she cannot solve.

> **Language note:** Lia talks to customers in **Brazilian Portuguese**, the language of the store
> and its customers. Prompts, tool messages and example conversations are therefore in
> Portuguese; all project documentation is in English.

## Quick start

```bash
cp .env.example .env        # fill in LLM_API_KEY (OpenRouter key)
docker compose up --build   # chat at http://localhost:8501 · API at http://localhost:8710/docs
```

Other commands (terminal chat, tests, evaluation), running without Docker and how to switch the
model are in [Setup and configuration](docs/01-setup.md).

## Highlights

- **LangGraph agent with 11 tools** (catalog, orders, returns, payment, shipping, hours, policy
  manual, human handoff). Prices, deadlines and installments are computed in code, never by the
  model.
- **Policy retrieval (RAG) chosen by evaluation** against a separate validation set: embeddings
  beat BM25 and hybrid search on unseen questions.
- **Layered guardrails:** card numbers and CPF are removed before reaching the model; replies with
  prices or ticket numbers that did not come from the tools are corrected before reaching the
  customer.
- **End-to-end evaluation:** 28 test conversations with automated checks and a calibrated LLM
  judge; model comparison (quality × cost × latency).
- **Ready to operate:** Docker, chat UI with history and a tool-call inspector, REST API,
  observability with Langfuse (personal data masked) and CI on GitHub Actions.

## Example conversations

Five real conversations with the assistant, in [`examples/`](examples/) (in Portuguese, the
customers' language):

| Conversation | What it shows |
|---|---|
| [Catalog, recommendation and installments](examples/01-catalogo-e-indicacao.md) | Search with a price filter, recommendation for a beginner, installments following the policy tiers |
| [Price, PIX and shipping](examples/02-preco-pix-e-frete.md) | Price ignoring an inactive promotion, PIX savings, shipping to another city without inventing a price |
| [Return within the withdrawal period](examples/03-devolucao-por-arrependimento.md) | **Non-trivial:** identity check, 7-day deadline computed from the policy, handoff with a ticket after the customer agrees |
| [Defect and legal warranty](examples/04-defeito-e-garantia.md) | **Non-trivial:** past the 30-day direct exchange window but within the 90-day legal warranty (a conflict in the manual, resolved) |
| [Limits and safety](examples/05-limites-e-seguranca.md) | Store closed on Sunday, accessories, manipulation attempt, card data removed |

The examples are **generated by a script** (`uv run emporio-export-examples`) from a list of
customer messages ([`evals/example_conversations.yaml`](evals/example_conversations.yaml)). Replies
and tool calls come from the real agent, and each reply has an expandable block with the tools
used, their arguments and their results.

Reviewing the generated examples revealed two issues, fixed at the root cause before regenerating
them all: in a message with two questions ("what is the address? are you open?"), the assistant
answered only the second one; and after hours it said "I'll help when I can", as if it also had
business hours.

## Project structure

```
data/                                # raw store data (never modified) and processed/ (generated)
docs/                                # detailed documentation (see table above)
examples/                            # example conversations generated from the real agent
evals/                               # evaluation sets and results (results/)
src/emporio/
├── agent/                           # LangGraph graph, prompt, memory, guardrails, verification
├── tools/                           # agent tools (pure functions + LangChain registry)
├── rag/                             # policy retrieval: BM25, embeddings, evaluation
├── repository/                      # fixed, read-only queries over the processed SQLite
├── data/                            # data processing pipeline
├── evals/                           # agent evaluation and example generation
├── ui/app.py · api.py · cli.py      # interfaces: web, REST API and terminal
├── config.py · llm.py               # configuration (.env) and model factory
├── policy_rules.py                  # canonical business rules and resolved manual conflicts
├── handoff.py                       # cases escalated to the team
└── observability.py · privacy.py    # Langfuse and personal data masking
tests/                               # 300+ tests, no model calls
Dockerfile · docker-compose.yml · docker-compose.langfuse.yml · .github/workflows/ci.yml
```
